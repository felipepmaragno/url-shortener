# Architecture Decision Records

ADRs are for durable decisions that future maintainers are likely to revisit, challenge, or need to understand before changing.

Use an ADR for decisions such as:

- implementation language;
- primary storage choice;
- ID allocation strategy;
- cache consistency strategy;
- redirect semantics;
- public API contracts with compatibility impact.

Do not create ADRs for small implementation conventions already owned by `docs/engineering.md` or an execution plan.
